1. System Overview

The Smart Book System is a library management web application. It lets users browse books, express interest, request to borrow, and read books — while admins manage books, users, and borrow records.

🎯 What this guide covers

This guide explains, in plain language, what happens behind the scenes when a user or admin takes an action. For every feature you will see:

  • ✅ Who can perform the action (Public / Logged-in User / Admin)
  • ✅ Which middleware runs (e.g. protect, adminOnly)
  • ✅ What database action is triggered (e.g. create, find, update, delete)
💡 Key Idea

Think of the system as a restaurant: the route is the menu item, the middleware is the security guard checking your ID, and the controller is the chef who actually prepares the dish (talks to the database).

Two Types of Users

RoleWhat they can do
USER Register, login, browse books, search, express interest, request checkout, view own records, read borrowed books
ADMIN Everything a user can do, plus: create/update/delete books, manage all users, view all borrow records, update any record status

2. Architecture & How Requests Flow

High-Level Architecture

📐 The Layers

The app is built in layers. Each layer has one job:

  1. Frontend (public/ folder) — HTML + JavaScript pages the user sees in the browser.
  2. Routes (routes/ folder) — Define the URL paths and decide which middleware + controller to call.
  3. Middleware (middleware/ folder) — Security checks that run before the controller.
  4. Controllers (controllers/ folder) — The "brain" that talks to the database and sends back a response.
  5. Models (models/ folder) — Define the shape of data stored in MongoDB.

🔍 What happens at each step
  1. Browser sends an HTTP request (e.g. GET /api/books).
  2. Route matches the URL and calls the middleware chain.
  3. Middleware checks authentication (is there a valid token?) and authorization (is this user allowed?). If a check fails, it stops the request and returns an error.
  4. Controller performs the actual database operation (find, create, update, delete).
  5. Response is sent back as JSON, which the frontend displays.

3. Understanding Middleware

Middleware are functions that run between receiving a request and sending a response. They act like security checkpoints.

🛡️ The protect Middleware

What it does

The protect middleware verifies that the request comes from a logged-in user. It does this by checking the JWT (JSON Web Token) sent in the request header.

Step-by-step: What protect does

📨 Request arrives
with "Bearer "
→
🔑 Extract token
from header
→
✅ Verify JWT
using JWT_SECRET
→
👤 Load user
from database
→
➡️ next()
continue to controller
⛔ When protect fails
  • No token → returns 401 "Not authorized, no token"
  • Invalid/expired token → returns 401 "Not authorized, token failed"
  • User no longer exists → returns 401 "User not found"

The actual code

const protect = async (req, res, next) => {
  let token;
  if (req.headers.authorization && req.headers.authorization.startsWith('Bearer')) {
    try {
      token = req.headers.authorization.split(' ')[1];
      const decoded = jwt.verify(token, process.env.JWT_SECRET);
      req.user = await User.findById(decoded.id).select('-password');
      if (!req.user) return res.status(401).json({ message: 'User not found' });
      next();
    } catch (error) {
      return res.status(401).json({ message: 'Not authorized, token failed' });
    }
  }
  if (!token) return res.status(401).json({ message: 'Not authorized, no token' });
};
✅ What protect gives you

After protect runs successfully, the controller can access the logged-in user via req.user (e.g. req.user._id, req.user.role).

🔐 The adminOnly Middleware

What it does

The adminOnly middleware checks that the logged-in user has the admin role. It must always be used after protect (because it needs req.user).

const adminOnly = (req, res, next) => {
  if (req.user && req.user.role === 'admin') {
    next();
  } else {
    return res.status(403).json({ message: 'Access denied: Admin only' });
  }
};
⚠️ Important

adminOnly returns 403 "Access denied: Admin only" if the user is not an admin. This is different from 401 (not logged in) — 403 means "you are logged in, but you don't have permission".

How Middleware is Combined

Middleware can be chained. For example, an admin-only route uses both:

router.post('/', protect, adminOnly, createBook);

4. The Three Database Collections

The app uses MongoDB (a NoSQL database). Data is stored in collections (like tables in a traditional database). There are three collections, defined by the models.

👤 Collection 1: users (Model: User.js)

Stores information about every user

FieldTypeDescription
nameStringUser's display name
emailString (unique)Login email
passwordString (hashed)Password is hashed (never stored in plain text)
roleString'user' or 'admin'
createdAt / updatedAtDateAuto-added timestamps
🔒 Password Security

When a user is created, a pre-save hook automatically hashes the password using bcrypt. The plain password is never stored. When logging in, the system compares the entered password against the stored hash.

📖 Collection 2: books (Model: Book.js)

Stores information about each book

FieldTypeDescription
titleStringBook title
authorStringBook author
isbnString (unique)Unique ISBN identifier
totalQtyNumberTotal copies the library owns
stockNumberCurrently available copies (defaults to totalQty)
contentStringThe book's text content (for reading)
💡 totalQty vs stock

totalQty = how many copies the library owns. stock = how many are currently available. When someone borrows a book, stock decreases. When they return it, stock increases.

🔁 Collection 3: borrowrecords (Model: BorrowRecord.js)

Tracks the borrowing lifecycle

FieldTypeDescription
userIdObjectId (ref: User)Which user owns this record
bookIdObjectId (ref: Book)Which book this record is about
statusStringinterested → pending → borrowed → returned
borrowDateDateWhen the book was actually borrowed
returnDateDateWhen the book was returned

6. The Borrow Lifecycle (State Machine)

A borrow record moves through four states. Each state represents a stage in the borrowing process. Not every transition is allowed — the system enforces a strict order.

The State Machine Diagram

INTERESTED
Wishlist
→
PENDING
Request submitted
→
BORROWED
Book in hand
→
RETURNED
Book returned

Allowed Transitions

FromCan go toWhat happens
interestedpendingUser requests checkout
pendingborrowed or returnedBorrowing: stock -= 1, sets borrowDate. Returning: stock += 1, sets returnDate
borrowedreturnedReturning: stock += 1, sets returnDate
returned(none)Final state — cannot change
⚠️ Invalid transitions are rejected

For example, you cannot go from interested directly to borrowed, or from returned back to pending. The system returns a 400 error: "Invalid transition from 'X' to 'Y'".

How Stock Changes Through the Lifecycle

📊 Stock tracking

  • interested / pending → stock is unchanged (no book taken yet)
  • borrowed → stock -= 1 (one copy is now out)
  • returned → stock += 1 (the copy comes back)

Example: A book has totalQty = 3 and stock = 3. When someone borrows it, stock becomes 2. When they return it, stock goes back to 3.

8. Glossary of Terms

TermMeaning
APIApplication Programming Interface — a way for software to talk to each other over HTTP
RouteA URL path (e.g. /api/books) that maps to a handler
MiddlewareA function that runs between the request and the response, often for security checks
ControllerThe function that handles the request and talks to the database
ModelDefines the structure of data stored in MongoDB
JWT (JSON Web Token)A secure token that proves a user is logged in. Sent in the Authorization header as Bearer
protectMiddleware that verifies the JWT and loads the logged-in user into req.user
adminOnlyMiddleware that checks the user has the admin role
req.userThe logged-in user object, attached by the protect middleware
MongoDBA NoSQL database that stores data in flexible documents
CollectionA group of documents in MongoDB (like a table)
DocumentA single record in a collection (like a row)
SchemaThe structure/definition of a document in a collection
bcryptA library that hashes passwords so they are never stored in plain text
populateA Mongoose feature that fills in referenced data (e.g. show book details in a borrow record)
HTTP Status 401Unauthorized — you are not logged in or your token is invalid
HTTP Status 403Forbidden — you are logged in but don't have permission
HTTP Status 404Not Found — the resource doesn't exist
HTTP Status 400Bad Request — the request is invalid (e.g. invalid status transition)
